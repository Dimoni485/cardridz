# Cardridz — учёт картриджей

Система учёта картриджей и печатающей техники: склад, выдача сотрудникам,
установка в принтеры, заправка, восстановление, списание, журнал операций и отчёты.

## Возможности

- Справочники: юрлица и их отделы (с номером кабинета), сервисные организации,
  модели принтеров, модели картриджей (с совместимостью с моделями принтеров),
  принтеры с привязкой к отделу, сотрудники с привязкой к отделу.
- Учёт каждого картриджа как отдельного экземпляра (инвентарный и серийный номера,
  стоимость, дата закупки, количество заправок).
- Полный жизненный цикл: приход, выдача, установка/снятие, возврат, заправка,
  восстановление, списание — с контролем допустимых переходов статусов.
- Журнал операций с контрагентом, документом, стоимостью и автором операции.
- Отчёты: остатки по моделям, движение за период, картриджи по сотрудникам,
  предупреждения о минимальном остатке.
- Месячный отчёт по использованию: сколько картриджей выдано каждому отделу
  каждого юрлица, стоимость картриджей и затраты на заправку/восстановление,
  итоги по отделам и по юрлицам.
- Учёт передачи картриджей в сторонние сервисные организации: организация,
  номер акта, ожидаемая дата возврата, стоимость и результат обслуживания,
  список картриджей, находящихся в сервисе, с контролем просрочки.
- Журнал ремонта принтеров в сервисных организациях: отправка, возврат,
  стоимость, результат и полная история; текущий ремонт отображается
  в карточке принтера.
- Выгрузка отчёта по обслуживанию в Excel за произвольный период: детализация
  по юрлицам, отделам, моделям и видам обслуживания, итоги по организациям
  и отделам.
- Пользователи с ролями и разграничением прав: администратор, редактор,
  только чтение. Администратор создаёт учётные записи, меняет роли, блокирует
  доступ и сбрасывает пароли.
- Встроенная справка «Помощь»: порядок заполнения справочников, статусы и
  операции, работа с сервисными организациями, описание отчётов и выгрузки
  в Excel, частые вопросы. Есть оглавление, поиск по инструкции и печать.
- Адаптивный интерфейс на русском языке.

## Быстрый старт (разработка)

Требования: Python 3.11+, Node.js 18+, PostgreSQL 17 (бинарники в
`/usr/lib/postgresql/17/bin`; другой путь задаётся через `PG_BIN`).

```bash
# 1. Виртуальное окружение и зависимости
python3 -m venv .venv
.venv/bin/pip install -r backend/requirements.txt

# 2. Конфигурация
cp backend/.env.example backend/.env
# отредактируйте DATABASE_URL, JWT_SECRET, ADMIN_PASSWORD

# 3. Локальная БД (кластер в .pgdata, порт 5433)
./scripts/dev_db.sh init

# 4. API на http://127.0.0.1:8000 (создаст схему и демо-данные)
cd backend
../.venv/bin/uvicorn app.main:app --reload --port 8000

# 5. Фронтенд с hot-reload на http://127.0.0.1:5173
cd frontend
npm install
npm run dev
```

Демо-доступ по умолчанию: **admin / admin** (меняется переменной
`ADMIN_PASSWORD` до первого запуска либо через интерфейс).

### Production-запуск

Соберите SPA — FastAPI автоматически раздаёт `frontend/dist` по адресу `/`:

```bash
cd frontend && npm install && npm run build && cd ..
./scripts/start.sh          # БД + API на 0.0.0.0:8000
```

Документация API (Swagger): `http://<host>:8000/docs`.

Приложение слушает `${APP_PORT}` (по умолчанию **8081**), PostgreSQL доступен

## Жизненный цикл картриджа

```
Поступление (создание картриджа)              → in_stock
in_stock  --выдача-->                          issued
in_stock / issued --установка-->               installed
installed --снятие-->                          in_stock
issued    --возврат-->                         in_stock
in_stock / issued --на заправку-->             in_refill
in_refill --возврат с заправки (+1 к счётчику)→ in_stock
in_stock / issued --на восстановление-->       in_restore
in_restore --возврат с восстановления-->       in_stock
любой статус, кроме written_off --списание-->  written_off
```

Недопустимые переходы возвращают HTTP 409 с пояснением. «Приход» оформляется
созданием картриджа (`POST /api/cartridges`) — отдельной операцией он не проводится.

## Юрлица, отделы и месячный отчёт

Структура справочников: **юрлицо → отдел → сотрудник и принтер**. Сотрудник и
принтер привязываются к отделу, отдел принадлежит юрлицу. У отдела можно указать
номер кабинета. При проведении операции (выдача, установка,
отправка на обслуживание и т. д.) система фиксирует юрлицо и отдел на момент
операции, поэтому изменения справочников не искажают историю.

Отчёт «Использование по юрлицам и отделам» (страница «Отчёты», выбор месяца):

- **Выдано картриджей** — количество операций выдачи за месяц.
- **Стоимость картриджей** — сумма цен закупки выданных картриджей.
- **Заправка и восстановление** — стоимость операций возврата с заправки
  и восстановления, отнесённая на отдел, за которым был закреплён картридж.
- **Ремонт принтеров** — стоимость ремонтов, закрытых в этом месяце
  и отнесённых на отдел.
- **Итого** — сумма стоимости картриджей, обслуживания и ремонта принтеров.
- Итоги считаются по каждому отделу и по юрлицу в целом.

Затраты на обслуживание сохраняют привязку к отделу, даже если картридж успели
вернуть на склад перед отправкой на заправку. Если картридж не был закреплён
ни за одним отделом, затраты попадают в строку без юрлица и отдела.

## Сервисные организации

Справочник **«Сервисные организации»** хранит сторонних подрядчиков по заправке
и восстановлению картриджей: наименование, ИНН, контактное лицо, телефон, email.

При отправке картриджа в сервис обязательно указываются организация, номер
акта/заявки и (опционально) ожидаемая дата возврата. Картридж получает статус
«на заправке» или «на восстановлении», а в его карточке отображаются организация,
дата передачи и ожидаемый возврат (просроченные выделяются красным).

При возврате фиксируются стоимость и результат: «Заправлен», «Восстановлен»,
«Не удалось», «Не подлежит восстановлению». Если картридж списывают прямо
из сервиса, организация и результат сохраняются в истории операций.

Отчёт **«Сторонние сервисные организации»** на странице «Отчёты» показывает
за выбранный месяц: сколько картриджей и принтеров отправлено и возвращено
по каждой организации, стоимость обслуживания и ремонта, а также сколько
картриджей и принтеров находится в сервисе сейчас, с отметкой просрочки.

## Ремонт принтеров

При отправке принтера в ремонт указываются сервисная организация, номер акта,
ожидаемая дата возврата и неисправность. Принтер автоматически получает статус
«В ремонте», а в его строке отображаются организация, дата отправки
и ожидаемый возврат.

При возврате фиксируются стоимость и результат:

- **Отремонтирован** — принтер автоматически переводится в статус «Работает».
- **Не удалось отремонтировать / не подлежит ремонту / другое** — принтер
  остаётся в статусе «В ремонте», решение о дальнейшей судьбе (повторный ремонт
  или списание) принимает ответственный.

Вся история ремонтов доступна по кнопке «История» в списке принтеров.
Стоимость ремонта попадает в отчёт по сервисным организациям и в затраты
отдела/юрлица, за которым закреплён принтер.

## Встроенная справка

Раздел **«Помощь»** (`/help`) доступен всем ролям и содержит инструкцию по
работе с системой:

- «Начало работы» — рекомендуемый порядок заполнения справочников;
- роли и права доступа;
- статусы картриджей и допустимые операции, пошаговые инструкции по приходу,
  выдаче, установке, заправке, восстановлению и списанию;
- принтеры и ремонт в сервисных организациях;
- юрлица, отделы и сотрудники (как затраты относятся на подразделения);
- сервисные организации, модели принтеров и картриджей;
- отчёты и выгрузка в Excel (состав листов);
- «Как изменять данные» (виден ролям с правом редактирования);
- «Управление пользователями» (виден только администратору);
- частые вопросы с раскрывающимися ответами.

Слева — оглавление с быстрым переходом, сверху — поиск по инструкции:
достаточно ввести «заправка», «отчёт» или «списание». Кнопка «Печать»
выводит инструкцию без элементов интерфейса.

## Пользователи и права доступа

Пользователями управляет администратор на странице **«Пользователи»**
(раздел виден только роли «Администратор»). Доступны создание учётной записи,
изменение ФИО и роли, блокировка («Доступ разрешён»), сброс пароля и удаление.

| Роль | Просмотр данных и отчётов | Изменение данных | Управление пользователями |
|------|---------------------------|------------------|---------------------------|
| Администратор | да | да | да |
| Редактор | да | да | нет |
| Только чтение | да | нет | нет |

Права проверяются на сервере: любая попытка изменить данные (POST/PATCH/DELETE)
от имени роли «Только чтение» возвращает `403`. В интерфейсе такие пользователи
видят предупреждение «Режим только для чтения», а кнопки изменения скрыты.
Выгрузка отчётов в Excel относится к чтению и доступна всем ролям.

Администратор не может понизить роль, заблокировать или удалить собственную
учётную запись, а также оставить систему без активного администратора.

Первый администратор создаётся при первом запуске из переменных
`ADMIN_USERNAME` / `ADMIN_PASSWORD` / `ADMIN_FULL_NAME` и получает роль
«Администратор». Пароль он меняет самостоятельно через «Сменить пароль»
или администратор сбрасывает его на странице «Пользователи».

## Выгрузка в Excel

На странице «Отчёты» в блоке «Сторонние сервисные организации» есть кнопка
**«Выгрузить Excel»**: выбирается период (по умолчанию — текущий месяц)
и скачивается файл `cardridz-service-<с>_<по>.xlsx`.

Файл содержит четыре листа:

1. **Обслуживание** — детализация: дата, юрлицо, отдел, тип объекта
   (картридж/принтер), модель, инвентарный номер, вид обслуживания
   (заправка, восстановление, ремонт), сервисная организация, документ,
   стоимость; внизу — итог за период.
2. **Итого по юрлицам** — суммы по заправке, восстановлению и ремонту
   по каждому юрлицу и общий итог.
3. **Итого по отделам** — те же суммы в разрезе юрлица и отдела с общим итогом.
4. **Итого по сервисным организациям** — суммы по видам обслуживания
   по каждому подрядчику и общий итог.

В отчёт попадают завершённые операции обслуживания: возврат с заправки,
возврат с восстановления и возврат принтера из ремонта за выбранный период.

## Схема БД

Схема создаётся автоматически при старте приложения (`Base.metadata.create_all`).
`create_all` создаёт только отсутствующие таблицы и **не изменяет** существующие,
поэтому при обновлении модели данных в разработке пересоздайте базу:

```bash
psql -h 127.0.0.1 -p 5433 -U postgres -d cardridz \
  -c "DROP SCHEMA public CASCADE; CREATE SCHEMA public;"
./scripts/start.sh
```

Для промышленной эксплуатации и последующих изменений схемы рекомендуется
подключить Alembic и версионировать миграции.
